# 课安管理端开发规划

对照产品架构图（首页 / 用户 / 代课 / 审核与举报 / 学校与校区 / 公告 / 数据统计 / 系统管理），规划 `web-kean` 页面与后端 `/api/admin/**` 补齐项。

约束不变：不做支付、地图、AI、代签。管理端只做运营治理，不替代用户端发单、选人、履约。

接口规格见 [`docs/api/admin.md`](../api/admin.md)。

---

## 1. 现状

| 层 | 已有 | 缺口 |
|---|---|---|
| 管理端 `web-kean` | 登录、布局、空 Dashboard、举报列表与处理弹窗 | 其余 7 个模块、详情页、统计图、侧栏菜单 |
| 后端 `kean` | 管理员种子账号；`/api/admin/reports` 列表与处理；用户表已有封禁/禁发/禁申/禁言；学校/校区/课程表；`operation_log`、`sys_config` 空表 | 管理端专用查询与写操作几乎全缺 |
| 鉴权 | 登录同一套 JWT；前端校验 `role=ADMIN`；举报接口在 Service 内 `requireAdmin()` | `SecurityConfig` 未按路径限制 `/api/admin/**`；普通用户接口不能给后台复用 |

**不能直接复用的用户端接口：**

- `GET /api/tasks`：强制本校，默认只返回 `WAITING` / `APPLYING`
- `GET /api/tasks/{id}`：跨校按不存在处理
- `GET /api/tasks/{id}/applications`：仅发布者可看
- `GET /api/schools|campuses|courses`：只返回启用项，无增删改、无停用项
- 通知接口：只读当前用户收件箱，不能发公告

后台一律走 `/api/admin/**`，统一要求 `role=ADMIN`。

## 2. 信息架构

侧栏与架构图对齐，路由全部挂在现有 `AdminLayout` 下。

| 菜单 | 路由 | 页面 |
|---|---|---|
| 首页概览 | `/dashboard` | KPI + 近 7 天趋势 + 状态分布 + 近期任务 + 待处理举报 |
| 用户管理 | `/users`、`/users/:id` | 列表 + 筛选；详情（资料 / 代课 / 履约 / 处罚） |
| 代课管理 | `/tasks`、`/tasks/:id` | 跨校列表；详情（信息 / 时间轴 / 申请） |
| 审核与举报 | `/reports`、`/reports/:id` | 现有列表升级为详情页（图中「申诉」= 现有 `report`，不另建申诉表） |
| 学校与校区 | `/catalog/schools`、`/catalog/campuses`、`/catalog/courses` | 学校 / 校区 / 课程三页或 Tab |
| 公告与消息 | `/announcements` | 草稿 / 已发布；发布后写入用户站内信 |
| 数据统计 | `/analytics` | 用户增长、任务趋势、学校排行、状态与举报分布 |
| 系统管理 | `/system/admins`、`/system/logs`、`/system/config` | 管理员账号、操作日志、站点配置 |

登录仍为 `/login`，非 `ADMIN` 拒绝进入。

## 3. 分阶段

### P0 运营能管人、管单、管举报（先做）

没有这三项，后台只是登录页。字段大多已在库里，缺的是管理接口和页面。

1. **基础设施**：`/api/admin/**` 角色拦截；写操作记 `operation_log`；统一分页与错误码。
2. **用户管理**：跨校列表、详情、封禁/解封、禁发/禁申/禁言、管理员重置密码。
3. **代课管理**：跨校全状态列表、详情、申请列表、管理员强制取消（`cancelled_by=ADMIN`）。
4. **举报补齐**：详情（证据图、对象跳转）、筛选、处理时发系统通知；`WARN` 目前只加 `reported_count`，要补通知。

### P1 目录与首页

5. **学校 / 校区 / 课程**：启用停用、增改；停用后用户端目录不再出现，已发布任务快照保留。
6. **首页概览**：四个 KPI、近 7 天发布/完成、状态饼图、两张工作台列表。

### P2 触达与看数

7. **公告**：新表 `announcement`；草稿/发布；按全站或学校推 `SYSTEM` 通知。
8. **数据统计**：与首页共用聚合接口，时间范围可调。

### P3 系统治理

9. **管理员账号**：创建/停用其他管理员；不能停用自己、不能删光最后一个管理员。
10. **操作日志**：只读查询。
11. **系统配置**：先做 `register.enabled`、`site.name`。

## 4. 页面说明

### 4.1 首页概览

| 区块 | 口径 |
|---|---|
| 用户总量 | `sys_user.role=USER` 且未删除 |
| 代课用户 | `completed_count > 0` 的学生 |
| 待处理举报 | `report.status in (PENDING, PROCESSING)` |
| 进行中任务 | `MATCHED + CONFIRMED + IN_PROGRESS` |
| 近 7 天趋势 | 按日：新发布数、完成数 |
| 状态分布 | 八种任务状态计数 |
| 近期代课 | 最近 8 条全状态任务 |
| 待处理举报 | 最近 8 条未结案举报 |

点击任务/举报跳到对应详情。

### 4.2 用户管理

筛选：学校、校区、性别、状态、关键词（用户名/昵称/手机号）。

列表字段：用户 ID、昵称、性别、学校、校区、状态、注册时间。表头统计：总数 / 男 / 女 / 封禁。

详情：

- 基本信息：账号、学校、评分、完成/取消/被举报次数、登录时间、三项限制开关
- 代课记录：其发布与申请的任务
- 履约记录：互评摘要
- 操作：封禁、解封、禁发、禁申、禁言、重置密码

不可管理 `ADMIN` 账号（改管理员走系统管理）。封禁后 JWT 仍按现有逻辑拒绝。重置密码后把该用户 Token 拉黑。

### 4.3 代课管理

筛选：学校、校区、状态、上课日期、关键词（课程名/教学楼/教室/任务 ID）。

列表：任务 ID、课程、发布者、代课者、上课时间、校区、状态、申请数。

详情：

- 基本信息（含酬谢、地点、性别要求、履约照片）
- 状态时间轴：用现有时间戳拼，不另建流水表（创建、申请、选人、双方确认、完成/取消/过期）
- 申请列表：申请人、留言、状态、时间（管理员只读，不代替发布者选人）
- 操作：强制取消（`WAITING`～`IN_PROGRESS` 均可；已完成/已取消/已过期不可）

取消原因必填，通知发布者与已选代课者。

### 4.4 审核与举报

架构图「申诉管理」对应现有 `report` 表，不新增申诉实体。

在现有列表上补：

- 筛选：状态、类型、对象类型、关键词
- 详情：举报人、对象、描述、证据图、处理结果、时间线（提交 / 处理）
- 处理动作保持 `WARN / RESTRICT / BAN / DELETE / REJECT`
- 处理后给被处理用户发 `SYSTEM` 通知；`DELETE` 取消任务时走管理员取消逻辑

### 4.5 学校与校区

| 页 | 能力 |
|---|---|
| 学校 | 列表（含停用）、新增、改名、启用/停用 |
| 校区 | 按学校筛选、新增、改名、启用/停用 |
| 课程 | 按学校维护 `course_code` + `course_name`、启用/停用 |

用户端发布目前自填课程名、`course_id` 可空。课程目录仍由管理员维护，供注册选校和后续联想，**不回改用户端强制选课**。

停用学校/校区：新发布不可选；存量任务与用户资料保留。有学生挂在该校时可停用、不可删除。

### 4.6 公告与消息

新表，状态 `DRAFT / PUBLISHED`。发布范围 `ALL` 或指定 `schoolId`。

发布时批量写入 `notification(type=SYSTEM)`。已发布不可改正文，只能停用（用户端不再展示，已发通知不撤回）。

用户端后续在消息 Tab 展示 `SYSTEM` 类型即可，本阶段管理端先能发出去。

### 4.7 数据统计

与首页同一套聚合，增加时间范围（默认 30 天）：

- 用户注册折线
- 任务发布 / 完成折线
- 学校任务量排行
- 任务状态饼图
- 举报类型饼图

不做实时大屏、不下钻到个人行为分析。

### 4.8 系统管理

- **账号**：管理员列表、创建、停用；登录名唯一；密码策略与种子管理员相同
- **日志**：读 `operation_log`（操作人、类型、对象、结果、IP、时间）
- **配置**：`site.name`、`register.enabled`（关闭后 `POST /api/auth/register` 拒绝）

## 5. 前端落地（`web-kean`）

技术栈保持 Vue 3 + Vue Router + Pinia + Element Plus + ECharts（统计页再加）。

| 目录 | 内容 |
|---|---|
| `src/layouts/AdminLayout.vue` | 八项菜单，高亮当前路由 |
| `src/views/users/` | 列表、详情抽屉或子页 |
| `src/views/tasks/` | 列表、详情 |
| `src/views/reports/` | 现有列表改为可进详情 |
| `src/views/catalog/` | 学校、校区、课程 |
| `src/views/announcements/` | 列表 + 编辑弹窗 |
| `src/views/analytics/` | 图表 |
| `src/views/system/` | 账号、日志、配置 |
| `src/api/admin-*.ts` | 按模块封装，不调用用户端列表接口 |

交互约定：列表统一分页 20；危险操作二次确认；状态用 Tag；详情优先抽屉，申请/证据需要宽屏时用子路由。

## 6. 后端必须补齐

详见 [`docs/api/admin.md`](../api/admin.md)。按优先级：

| 优先级 | 能力 | 现状 |
|---|---|---|
| P0 | `/api/admin/**` 角色拦截 | 仅举报 Service 内校验 |
| P0 | 用户列表 / 详情 / 封禁解封 / 三项限制 / 重置密码 | 字段有，接口无 |
| P0 | 任务跨校列表 / 详情 / 申请列表 / 强制取消 | 用户端接口不可复用；`isAdmin()` 未接到取消 |
| P0 | 举报详情、筛选、处理通知 | 列表+处理已有，详情与通知缺 |
| P0 | 操作日志写入 | 表已有，无实体与切面 |
| P1 | 学校/校区/课程 CRUD | 仅公开只读 |
| P1 | 首页概览聚合 | 无 |
| P2 | 公告表 + 发布推送 | 表不存在 |
| P2 | 统计接口 | 无 |
| P3 | 管理员账号 CRUD | 仅启动种子 |
| P3 | 日志查询、`sys_config` 读写 | 表已有，无代码 |
| P3 | `register.enabled` 生效 | 配置未读取 |

库表：`announcement` 需新建；`operation_log`、`sys_config` 已建空表。

## 7. 验收

1. 普通用户 Token 访问任意 `/api/admin/**` 返回 `40300`。
2. 管理员能跨校搜到任意状态任务，学生端仍只看本校可接单任务。
3. 封禁用户无法登录；禁发/禁申/禁言分别挡住发布、申请、私聊。
4. 管理员取消进行中任务后双方收到通知，状态为 `CANCELLED` 且 `cancelled_by=ADMIN`。
5. 处理举报后目标用户收到系统通知，`WARN` 不再是只改计数。
6. 停用校区后注册与发布选不到该校区，旧任务详情仍显示名称。
7. 发布全站公告后，目标用户消息列表出现 `SYSTEM` 记录。
8. 写操作在操作日志中可查。
